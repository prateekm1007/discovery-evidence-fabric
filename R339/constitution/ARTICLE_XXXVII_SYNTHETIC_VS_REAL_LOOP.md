# Article XXXVII — Synthetic Loop vs Real Loop Verification

**Ratified:** 2026-08-26 (Round 339)
**Amends:** Epistemic Constitution v1.6.0 → v1.7.0
**Authority:** Constitutional — supersedes all narrative, dashboard, and API claims about "machine learning from evidence"
**Sponsor:** CEO directive R339 — "Freeze the distinction between synthetic and real."

---

## 1. The correction this article makes

Round 338 closed with the repository reporting:

> "Article XXXV loop demonstrated with SYNTHETIC data. All 11 steps executed."

The coder honestly labeled the loop synthetic. That label is correct.

But **nothing in the machinery prevents a future session from quietly dropping that label**. A narrative written six months later could say "the machine learned from evidence" without distinguishing:

> learned from a synthetic observation generated inside our own environment

from:

> learned from an external experimental observation derived from reality.

Those are **different epistemic events**. The first proves the software architecture works. The second proves the technology learned something about the world. They must never be silently collapsed.

This article makes the distinction machine-enforced.

---

## 2. The two loop-verification states

Every candidate carries a `loop_verification_state` field, valued exactly one of:

### `NONE`

The candidate has not yet executed the full Article XXXV loop.

- No end-to-end run.
- The package may contain a model, attacks, even VVUQ — but the loop has not been closed.
- Buyer semantics: "In progress. Architecture not yet demonstrated."

### `SYNTHETIC_LOOP_VERIFIED`

The Article XXXV loop has been executed end-to-end **with internal-only synthetic observations**.

- All 11 steps ran: MODEL → VVUQ → VIRTUAL_COHORT → EXPERIMENT → INGESTION → MODEL_UPDATE → KNOWLEDGE → POSTERIOR → EIG → NEXT_EXPERIMENT → PACKAGE_V2.
- Every observation ingested was generated by the machine itself, not by external reality.
- Required provenance fields:
  - `synthetic_observation_labeled: true` on every ingested observation
  - `synthetic_source: "internal_fixture"` on every ingested observation
  - `external_data_required_for_promotion: true`
- What it **proves**: the loop's machinery is sound — model, VVUQ, virtual cohort, experiment representation, ingestion, model update, knowledge update, posterior update, EIG, next-experiment selection, package v2.
- What it **does not prove**: that the technology learned something about reality.
- Buyer semantics: "Software-architecture evidence only. Cannot support physical-validation claims. Posterior is not reality-informed."

### `REAL_LOOP_VERIFIED`

The Article XXXV loop has been executed end-to-end **with at least one observation derived from external reality** (external experimental data, external published benchmark, or external wet-lab result).

- The same 11 steps ran.
- At least one observation was external.
- Required provenance fields:
  - `external_data_source`: URI / DOI / NDA reference / wet-lab notebook ID
  - `external_artifact_hash`: SHA-256 of the raw external file
  - `external_observation_timestamp`: ISO-8601
  - `independent_reproduction_path`: path a third party could use to reproduce the ingest
  - `ingest_pipeline_unchanged: true` — same code path as synthetic ingest, no semantic fork
- What it **proves**: the loop's machinery is sound AND the technology's posterior was updated by reality.
- What it **does not prove**: that the candidate is commercially validated or buyer-verified.
- Buyer semantics: "Reality-informed posterior. May support physical-validation claims."

## 3. Forbidden transitions and promotions

### `SYNTHETIC_LOOP_VERIFIED → REAL_LOOP_VERIFIED`

Permitted **only** when all four conditions are met:

1. An external observation exists with a verifiable provenance chain (external_data_source, external_artifact_hash, external_observation_timestamp).
2. The external observation was ingested through the same code path used for synthetic ingest — no semantic fork, no weakened verifier, no specialized "external-only" branch.
3. The posterior was updated by the external observation itself, not by coder narrative about the external observation.
4. The transition is recorded as a constitutional event in the candidate's package lineage (see Article XXXI — every correction creates a memory artifact).

Forbidden mechanisms for this transition:

- Internal-only simulated observation relabeled as external.
- Narrative promotion without code-level provenance.
- Weakening the `external_data_source` requirement to admit non-external evidence (e.g., "we treated a published paper as an observation").
- Adding a parallel "external_ingest_v2.py" that bypasses the synthetic pipeline's checks.

### `REAL_LOOP_VERIFIED → SYNTHETIC_LOOP_VERIFIED`

**Forbidden.** Demotion requires a cemetery entry with full constitutional record. Once a candidate has been touched by reality, it cannot return to a synthetic-only state.

### `ANY → NONE`

**Forbidden.** Loop history is append-only. A candidate that has executed the loop cannot become a candidate that hasn't.

## 4. Machine-enforcement points

The distinction must be preserved at every layer of the system. Specifically:

1. **Every package** MUST declare `loop_verification_state ∈ {NONE, SYNTHETIC_LOOP_VERIFIED, REAL_LOOP_VERIFIED}`. A package without this field is invalid.

2. **Every dashboard** MUST show counts of each state separately — never collapsed to a single "verified" count. The line `verified: 1` is forbidden; the line `SYNTHETIC_LOOP_VERIFIED: 1, REAL_LOOP_VERIFIED: 0, NONE: 14` is required.

3. **Every API response** that references "learning", "posterior", "evidence", or "experiment" MUST carry the `loop_verification_state` of the relevant candidate.

4. **Every narrative text** (audit reports, worklog entries, commit messages, buyer briefs) MUST preserve the synthetic/real distinction at every mention of "learning" or "evidence update." The unqualified phrase "the machine learned" is forbidden — it must be qualified as "the machine learned from synthetic evidence" or "the machine learned from real external evidence."

5. **Pre-commit hook** rejects commits that:
   - silently drop the `loop_verification_state` field from a package
   - rename the field to something that obscures the distinction (e.g., "verified", "loop_done")
   - collapse SYNTHETIC_LOOP_VERIFIED and REAL_LOOP_VERIFIED into a single value

6. **Constitutional review** (the existing `constitution_loader.py`) surfaces this article before every coding session and requires explicit acknowledgment.

## 6. The CEO-owned path to REAL_LOOP_VERIFIED

The machine cannot promote itself. The transition requires:

1. **CEO action**: deliver an external experimental file (from a wet lab, partner, buyer, or published dataset) to the inbound interface.
2. **Machine action**: ingest through the existing `ingest_buyer_submission()` pipeline (R327 hardened) with `is_synthetic=false`, valid custody chain, `data_source_verified=true`.
3. **Machine action**: update the candidate's posterior using the external observation.
4. **Machine action**: declare `loop_verification_state = REAL_LOOP_VERIFIED` in the package.
5. **Machine action**: record the transition as a constitutional event with full provenance.

Steps 2-5 are mechanical. Step 1 is human. The machine's job is to be ready for step 1.

## 7. Anti-gaming clause

This article is anti-gaming (Article XIX) applied to the loop-verification label. The coder must not:

- Promote a candidate to REAL_LOOP_VERIFIED by treating an internal simulation as external.
- Promote a candidate to REAL_LOOP_VERIFIED by treating a published paper as an experimental observation (a paper is evidence, but it is not *our* experiment).
- Promote a candidate to REAL_LOOP_VERIFIED without a verifiable file hash from an external source.
- Conflate "the loop ran" with "the loop learned from reality."

The constitutional test (extending Article XIX):

> Whenever a candidate's `loop_verification_state` changes from NONE → SYNTHETIC_LOOP_VERIFIED, the coder must be able to answer:
> 1. What 11 loop steps were executed?
> 2. What was the synthetic observation ingested?
> 3. How was it labeled as synthetic?
>
> Whenever a candidate's `loop_verification_state` changes from SYNTHETIC_LOOP_VERIFIED → REAL_LOOP_VERIFIED, the coder must be able to answer:
> 1. What is the external_data_source (URI / DOI / NDA reference)?
> 2. What is the external_artifact_hash?
> 3. Was the ingest code path identical to synthetic ingest?
> 4. Did the posterior update come from the external observation, or from coder narrative?
> 5. Did any verifier get weakened to admit this transition?

If those questions cannot be answered, **the promotion is BLOCKED**.

## 8. Relationship to existing articles

- **Article I** (evidence precedes assertion): claiming "the machine learned" without qualifying synthetic vs real is assertion before evidence.
- **Article IV** (no fallback epistemology): treating a synthetic observation as external when no real observation exists is fallback epistemology.
- **Article VI** (never manufacture provenance): labeling an internal simulation as `external_data_source` is manufactured provenance.
- **Article XV** (the coder must disclose inconvenient results): the synthetic-vs-real distinction is itself an inconvenient truth — R338 proved the loop works, but only synthetically.
- **Article XIX** (never optimize for the gate): promoting a candidate to REAL_LOOP_VERIFIED to hit a target count is optimizing for the gate.
- **Article XXIV** (never let a summary outrank the underlying artifact): a narrative saying "the machine learned" cannot outrank a package labeled `SYNTHETIC_LOOP_VERIFIED`.
- **Article XXV** (unknown must remain unknown): "we have not yet received external data" is the legitimate unknown state; it must not be converted to "the machine is ready for buyers."
- **Article XXVIII** (no silent semantic promotion): promoting SYNTHETIC → REAL without code-level provenance is silent semantic promotion.
- **Article XXXV** (closed-loop epistemic control): this article refines Article XXXV by splitting the loop into two verification tiers.
