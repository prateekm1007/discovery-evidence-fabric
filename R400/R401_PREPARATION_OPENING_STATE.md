Today's production-shape run (R400/PRODUCTION_PHYSICS_RUN_930eca8b.json)
demonstrated the ceiling honestly:

- ONE problem → ONE primary mechanism (the "self-expanding metal
  mesh" synthesis) + 5 exploration-grid variations
  (constraint_first / cross_industry_transfer / mechanism_inversion /
  multi_physics_hybrid / simplification — the R377/R378 grid).
- The evidence bundle reached the mechanism path as 5 classified
  items (1 DIRECT_SUPPORT + 4 ANALOGY) — evidence-CLASSIFIED, but not
  yet STRUCTURED mechanism-space data.
- The candidate was honestly REJECTED (evidence verification failed;
  design-learning KILL: 0.000412 < 0.05 mL/min required minimum even
  while BEATS_BASELINE 12.96×).

This is exactly the CEO's diagnosis: the machine reliably runs the
RESEARCH loop; the INVENTION core is still one-synthesis-deep. R401
replaces the single-mechanism core with a structured mechanism space.

## 2. The R401 requirement (from the directive, verbatim constraints)

Every evidence item entering invention becomes STRUCTURED DATA with
at minimum: `source, claim, observed_effect, system, intervention,
mechanism, boundary_conditions, constraints, failure_mode,
confidence, provenance` — then multiple candidate mechanisms are
DERIVED from the bundle via transformation operators:

1. `DIRECT_TRANSFER`
2. `CROSS_DOMAIN_ANALOGY`
3. `GEOMETRIC_TRANSFORMATION`
4. `BOUNDARY_CONDITION_CHANGE`
5. `FAILURE_PATH_INVERSION`

**Repeating the same prompt five times is NOT five generators** —
each operator needs a materially different search constraint and an
independently traceable derivation path. (Existing partial substrate
to build on — measured: the exploration grid's 5 modes at
`discovery_fabric/engine/` already produce 5 distinct invention
specifications per run; the R401 operators are a SUPERSET with
different semantics — transfer/analogy/geometry/boundary/inversion
vs the current first/inversion/hybrid/simplification set. The gap
analysis and the per-operator search-constraint design is the first
R401 task.)

Each serious candidate must carry: `mechanism_graph,
evidence_bundle, constraint_set, predicted_effect,
known_failure_modes, novel_design_variable, testable_prediction` —
and go through the SAME downstream gates (PLAUSIBILITY, CAD,
PHYSICS, BASELINE, ATTACK). A candidate that cannot produce a
testable prediction is not an invention candidate.

## 3. VERIFY upgrade (evidence-vs-mechanism support, not quotation)

The six-axis evidence understanding (R394) and the five semantic
relations (SUPPORTS / PARTIAL_SUPPORT / CONTRADICTS / IRRELEVANT /
UNKNOWN) exist; R401 makes the relation TARGET the mechanism claim:
does the evidence actually support the MECHANISM the candidate
asserts, with `PARTIALLY_SUPPORTS` and `NOT_ENOUGH_EVIDENCE` as
first-class outcomes and contradictory evidence remaining VISIBLE
through synthesis (never absorbed).

## 4. Adversarial separation

The attack stage must not be the synthesis model criticizing itself.
Where practical: separate GENERATOR from ATTACKER (different model
family / independent reasoning context / independent generation
paths — the R396 ensemble already carries family separation; extend
it to the attacker role). The attacker seeks: mechanism failure,
boundary-condition failure, evidence contradiction, baseline
equivalence, implementation impossibility, measurement ambiguity.

## 5. Definition of done (R401)

The machine takes a single problem and produces:

```
MULTI-SOURCE EVIDENCE
  → STRUCTURED MECHANISM SPACE
  → MULTIPLE DISTINCT CANDIDATES
  → PHYSICAL CONSTRAINTS
  → CAD
  → PHYSICS
  → BASELINE COMPARISON
  → INDEPENDENT ATTACK
  → TESTABLE PREDICTION
```
